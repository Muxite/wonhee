What tops out first, by shape of work

Each row is one kind of work running alone at full tilt. Cells are the share of each ceiling it reached; a highlighted cell is at 90% or more. Dense math hits the 300 W power limit while the memory system has room; streaming memory saturates the memory controller at half the power; tiny kernels leave the GPU idle and pin one CPU thread.

Input size

Warm call time scales with the amount of input (images, seconds of audio), while VRAM stays almost flat: the model's weights dominate memory. Pixel count barely matters because the models resize internally.

Profiler effect

Nsight slows steady-state work beyond the ±3% tolerance set before the runs, so every rate on this page comes from profiler-off runs. Traced runs are used only for what the GPU did inside a call.

Evidence audit of the earlier runs

Before adding runs, the existing ledger was checked against what the evidence needs. These gaps shaped every experiment above: interleaved order, matched baselines, cache state as a condition, and profiler-off rates.

Method and limits

  • Every job runs in its own Docker container under gauge. Container CPU and RAM come from cgroup v2; VRAM per process and device readings (power, clocks, engine use, PCIe) from NVML every 100 ms.
  • Each experiment file states its question, measure, analysis rule, tolerance and stopping rule before it runs. Conditions are interleaved and each round shuffled with a fixed seed; solo references run inside the same file as their co-runs.
  • Page cache and the CUDA JIT cache are set explicitly per run. Each run records its exact command, input hashes and image digest.
  • Ranges in brackets are the minimum and maximum over repeats; most cells have two or three. One GPU model, one machine: ratios are expected to carry over better than absolute numbers.
  • Device readings are whole-GPU. In co-runs they belong to all jobs together; per-job speed comes from each job's own counters.
